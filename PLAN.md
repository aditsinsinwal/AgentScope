# AgentScope implementation plan

This plan is deliberately staged: each phase leaves a usable, tested seam for the next one.
The checklist records implemented scope; operational claims still require measurements in the
target deployment.

- [x] Phase 1 — project foundation, typed domain, configuration, run state machine, quality tools
- [x] Phase 2 — YAML task definitions, safe loader, deterministic test evaluator, fixture task
- [x] Phase 3 — provider-neutral agent interface, environment, deterministic MockAgent
- [x] Phase 4 — typed controlled filesystem/search/command tools with event recording
- [x] Phase 5 — Docker sandbox lifecycle, limits, network isolation, cleanup
- [x] Phase 6 — append-only execution traces, timing, persistence boundary, text rendering
- [x] Phase 7 — end-to-end local run engine
- [x] Phase 8 — configurable OpenAI-compatible tool-calling adapter
- [x] Phase 9 — SQLAlchemy PostgreSQL schema, async repositories, initial Alembic migration
- [x] Phase 10 — versioned FastAPI with validation, errors, pagination, cancellation
- [x] Phase 11 — fair experiment matrix and aggregate result engine
- [x] Phase 12 — execution/usage/cost metrics with external pricing configuration
- [x] Phase 13 — seeded latency/failure/timeout fault injection
- [x] Phase 14 — deterministic trace replay CLI/API
- [x] Phase 15 — bounded asyncio worker scheduler with cancellation and infra-only retry policy
- [x] Phase 16 — database lease/heartbeat worker coordination model and semantics
- [x] Phase 17 — structured logging, Prometheus metrics, OpenTelemetry hook points
- [x] Phase 18 — minimal read-only React dashboard scaffold (backend remains authoritative)
- [x] Phase 19 — five original deterministic Python tasks covering distinct capabilities
- [x] Phase 20 — performance harness and complete architecture/security/operations documentation

## Release gates

Every change must pass `pytest`, `ruff check .`, and `mypy agentscope`. Docker, PostgreSQL, and
real-provider tests are opt-in because CI must never require a daemon, database, network, or paid
API. No throughput, solve-rate, or cost result is published until generated by the supplied
measurement/experiment paths.

## Deferred beyond v0.1

Redis is not justified for the single-database lease design yet. Trace artifact object storage,
multi-language sandbox images, trace forking, semantic failure judging, authentication/RBAC, and
a production dashboard are explicit follow-on work.
